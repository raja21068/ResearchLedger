# Architecture and operating model

```text
                          _inputs/topic.md or ideas.json
                                      │
                              S1 idea selection
                                      ▼
                           S2 LaTeX draft & spec
                       {PFVAL, PFFIG result placeholders}
                                      │
                              S3 referee review
                                      │
                      S4 PaperCompiler-style codegen
                         ├── static repository guard
                         ├── Docker pip install (offline default)
                         ├── Docker experiment run (network none)
                         └── checked results.json with provenance
                                      │
                           S5 fill, revise, review
                         ├── measured macros / generated plots
                         ├── compile & model-score loops
                         └── automated threshold gate
                                      ▼
                         researchctl audit (human gates)
```

## Checkpoint protocol

1. Resolve the stage's source inputs and dependent artifact hashes, user settings, core toolchain source, and applicable prompt/template files.
2. Compute a SHA-256 **before** executing a stage.
3. Run the stage and validate its primary artifact.
4. Recompute the input signature; reject a stage if the inputs changed mid-execution.
5. Atomically write the completed checkpoint (input SHA-256, primary artifact SHA-256, and supporting-output signature covering final PDF, result spec and generated repository as applicable).
6. On resume validate in strict stage order; invalidate the first missing or altered stage and all later stages.
7. Report **effective state** from the valid checkpoint chain, keeping historical transitions as audit history.

This costs disk reads: input datasets are SHA-256 hashed in chunks at each stage. For very large datasets the additional I/O is intentional, to avoid trusting altered data silently. External Claude skills installed outside the project are not fully checkpoint-fingerprinted; changes to these skills can require a manual rerun.

## Quality model

S5's mean scores are generated by a model and remain subjective. Target attainment is a workflow gate only. A publication requires independently inspected algorithms, a bibliography audit, statistics, uncertainty analysis, reproducibility on the intended data, and relevant ethical approval or exemption. The quality audit never sets `publication_ready=true` based on automated claims.
